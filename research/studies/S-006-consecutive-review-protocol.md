# S-006 · Consecutive unattended reviews and a separate natural-input window

Mike authorized this bounded extension during the Reservoir Scope 0.14 research review. The executable protocol is frozen only after isolated collector qualification, before T0 and before new source outcomes are read. Its exact UTC boundaries, code identities, source allowlist and limits are in [protocol.json](../outputs/2026-09-17-bounded-followups/protocol.json). This is an observation, not an instruction to the flywheel or either Being.

The primary frame is the first ten consecutive existing controller runs with actor `claude-heartbeat`, adapter `subprocess`, and start in the seven-day interval beginning at T0. Run IDs and start clocks establish order. Failed, cancelled, incomplete and no-input runs remain eligible. Other actors are counted separately, not silently treated as unattended flywheel work. Each selected run has a 48-hour follow-up ending no later than T0 plus nine days. Late terminal receipts remain censored.

Runs are the denominator because the retained historical system supplies durable controller receipts but does not establish a durable queue-admission stream. A round's processed and unprocessed canonical shortlist remains visible, in original order. Repeated queue appearances, distinct reports and same-source families remain different counts. Missing queue evidence stays unknown. This protocol does not invoke the owning queue, review or controller commands.

For each processed episode, subsequent evidence-coded review separates the original author's passage and source subject, reviewer disposition, source or test evidence, response type, actual commit versus commit debt, activation, and measured outcome. A successful controller exit or `addressed_change` label proves none of the later stages. Test-only changes, no change, reviewer-discovered issues and unprocessed material remain explicit. Total elapsed run time can be measured; unavailable phase clocks are not reconstructed from narrative estimates.

## Separate provider opportunity window

All physical dispatches in a separately registered 24-hour interval are eligible, with 120 seconds for terminal outcomes. The original shared provider start was prospectively superseded by [provider-amendment.json](../outputs/2026-09-17-bounded-followups/provider-amendment.json), after the observer preflight and its collector qualification. The provider window is September 17, 2026 at 20:43:05 UTC through September 18 at 20:43:05 UTC; its outcome allowance ends at 20:45:05 UTC. The consecutive-run and S-008 windows retain their original September 17 start at 20:35:39 UTC, September 24 intake cutoff and September 26 final cutoff.

The declared observation surface is the existing September 8 private spool identified in TRACE.md. The [preflight receipt](../outputs/2026-09-17-bounded-followups/provider-preflight.json) found more than the allowed 20,000 event names. It did not select a newest identity from that incomplete enumeration or read any outcome. Coverage is unavailable within the frozen scope, so an exhaustive provider denominator cannot currently be established. This limitation is retained with each provider summary. No new spool is substituted automatically, and no observer is enabled or service restarted here.

Dispatch/outcome identity, input availability, release declarations and retained raw hashes are checked. Missing outcomes, unavailable inputs, recording gaps and late responses remain separate. A marker-bearing input is only a candidate; exact old/new scanner replay and contextual assessment are required before calling it an eligible repair opportunity. Release identity must also be independently bound. Provider return, accepted journal, natural benefit and felt benefit are distinct endpoints. Zero observed markers without current coverage evidence is not zero opportunity frequency.

## Capture and verification boundaries

The source allowlist permits the controller `runs` directory; direct dated `claude-heartbeat_<unix>_<name>` packet metadata tied to selected run IDs; at most forty claim/summary files per packet directory; exact original introspection reports referenced by the read manifest; the declared provider event files; and exact hash-addressed raw references. Lease files, authority tokens, databases, executable source commands, models, services and recursive workspace searches are excluded. Controller JSON is projected without credentials; original source hashes remain provenance.

Live reads are stable-checked and capped at 8 MiB per file, 256 MiB per capture, 20,000 names and ten seconds per directory, and 150 seconds per collector. Provider raw artifacts are limited to 256 KiB; at most 5,000 dispatches are retained. Exceeding a cap is an explicit coverage failure, never a complete smaller census. Unknown schemas require review. Every refresh creates new capture/status/receipt files; offline verification reproduces the summaries without live reads.

The successful finish is an auditable bounded cohort with honest dispositions and shortfalls, not a guaranteed useful change. No outcome is complete merely because this protocol and collector are ready. The existing S-007 daily process and ledger remain unchanged.
