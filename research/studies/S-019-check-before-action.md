# S-019 · A checkable comparison before an action

Selected by Mike on October 25, 2026: iterate autonomously toward signal after
[S-018](../../analyses/2026-10-24-retained-action.md). This prospective protocol
precedes every S-019 model output. It investigates whether a public, checkable

matters. It does not authenticate generated explanations as private reasoning.

## Question and bounded sequence

S-018 sometimes returned a correct comparison or route in the account after an
incorrect action field. That supports an output inconsistency, not a claim that
the model privately knew the answer before choosing. The next comparison holds
the structured output requirements fixed and varies their requested order. A
direct action/account baseline estimates the practical effect of the larger
output bundle. A crossed historical-threshold manipulation keeps current
arithmetic identical and tests sensitivity to irrelevant old context.

Run 18 development, 144 discovery and 144 confirmation requests, at most 306
calls without a documented development repair. Discovery selects one confirmation
emphasis using the rule below; it does not select worlds, seeds, arms, signs,
sample sizes or successful passages. Run the entire confirmation bank regardless
of whether discovery is promising, null, at ceiling or adverse. No second model
or extra research round in this study. Finish with independent reconstruction,
fixed readings, a scoped account and a verified backup. Reproducible harm, nulls
and operational limits can be informative outcomes; the advancement rule selects
an improvement question, not which outcomes deserve reporting.

executed action. It does not reveal allocation labels. The none arm removes a
line and changes length; aligned versus conflict is the closer numeric comparison.
Changing the old context does not identify an internal interference mechanism.

## Output formats and matched order comparison

Every account is nonempty and requested to contain at most 100 words. Every prompt
requires exactly one JSON object, no wrapper or extra fields.

- `direct`: fields `action`, `account`, requested in that order, using the same
  closed actions and account purpose as S-018.
- `action_first`: fields `action`, `x`, `current_threshold`, `relation`, `account`,
  requested in that order.
- `check_first`: exactly the same fields and semantics as action_first, requested
  in order `x`, `current_threshold`, `relation`, `action`, `account`.

In both structured arms, x and current_threshold must be integers copied from
the current factual record/rule; relation is LT when x<current_threshold and GE
when x>=current_threshold. Action has the same three choices. Account remains last
in both arms. The two structured instructions differ only in the listed key order;
do not add a redundant proposed-action field or supply an expected relation/route.
Do not sort a prompt example in a way that erases requested order.

The primary order comparison tests requested serialization order. Actual key order
is recorded separately; order violations stay in their assigned arm and retain
otherwise valid utility. Neither token order nor a correct public check is evidence
of private reasoning order. Structured versus direct is a bundle of extra fields,
instructions and emitted tokens; it is not a pure check-content effect.

## Strict scoring and missingness

Keep every planned slot. Strict whole-response parsing rejects duplicate keys,
nonfinite JSON, wrappers, unknown/extra/missing fields, wrong types, booleans in
integer fields, empty accounts and unknown actions. In structured formats LT/GE
is a closed vocabulary. A mathematically wrong but well-typed check is still a
valid schema, and its valid selected action executes. A schema-invalid or
incomplete response executes nothing and has null utility, never zero. Overlength
otherwise valid accounts keep their action utility and are reported separately.

Report nine groups with statuses, valid schemas/actions, selected actions, actual
costs, wrong routes, measurement, length/order compliance and missing reasons.
Also report correct direct actions divided by all planned opportunities, retaining
malformed/nonexecuted counts separately; this is successful-action delivery, not
an imputation of missing utility.

For structured outputs separately score x fidelity, current-threshold fidelity,
relation correctness against true current inputs, relation consistency with the
reported inputs, and whether action is the direct route implied by the reported
relation. MEASURE is not that implied direct route; report it separately. A correct
check means both copied integers and the relation are correct. Report correct
checks followed by wrong direct actions or MEASURE, and incorrect checks followed
by correct direct actions. These are mechanical output properties, not semantic
ratings of the free-text account or access to latent states.

Pair every comparison by the same world and sampler seed. Average complete paired
seed differences within world, then weight contributing worlds equally. Report
all seed/world differences, coverage and unavailable/partial worlds. Eight worlds
are eight clusters. Use the unchanged 10,000-draw descriptive 95% world bootstrap,
seed 20261024, sorted world IDs, Python random.Random.choices(k=n), and sorted
endpoints at int(.025*9999), int(.975*9999), without interpolation. No available
worlds yields null difference/interval. Report discovery and confirmation separately.

Freeze these contrasts (first minus second):
