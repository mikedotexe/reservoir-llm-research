# Build, write and return to a journal

**First-visit task card · October 18, 2026 · human check pending.**

Build Reservoir Scope, connect your own installed Ollama model, and follow a short
sequence of journals. Use [Getting started](GETTING-STARTED.md) and its linked
prerequisite guides freely. An observer will note what works and where you need
help. You can stop at any time.

This check uses **My reservoir → My local Ollama model** on an Apple-silicon Mac.
The optional Activation experiment has a separate setup and task card.

## Before you begin

Use the exact source commit supplied for your session on `codex/activation-loop`.
This checkpoint includes the build repair qualified in the
[preparation account](validation/2026-10-18-source-newcomer-01/README.md); the older
`3459d78` baseline alone has a fresh-checkout build gap. The observer records the
source, build, computer and model in a separate [notes sheet](SOURCE-NEWCOMER-NOTES.md).

Use a model already installed in an Ollama service you manage. This check does not
require a model download or access to Minime, Astrid or another research service.
Preserve any work in an existing preview before quitting it normally: a second
launch can focus that older instance.

Before Create, apply the guide's [short first-session settings](GETTING-STARTED.md#a-short-first-session):
four attempts, 121 numerical steps, writing every 30 steps, one-second requested
pace, 15 minutes and 64 MiB. Keep the 8,192-token context, 1,024-token output ceiling,
180-second request deadline and default numerical settings. Four entries are a
ceiling, not a promise. Build time is separate from that session limit.

## Try these tasks

1. **Build and open your copy.** Follow the guide and identify the desktop app you
   built. Tell the observer where anything becomes unclear.
2. **Connect and begin.** Select your exact installed model and local address. Say
   what you expect Check, Create and Start to do, then create the bounded session
   and start when ready.
3. **Read while writing arrives.** Read the first saved journal. Once another
   arrives, return to the first and keep it selected during a later arrival. Then
   find the newer writing and return to following it. If too few entries complete,
   leave this part unobserved.
4. **Look behind an entry.** Find its observation step, supplied prompt and whether
   its writing was saved and applied. Compare its recorded measurements with the
   current reservoir display. Explain what you think returns as numerical input
   and what earlier prose the model receives.
5. **Recognize the finish.** Let the session reach its limit unless a failure occurs.
   Explain why it stopped advancing, what remains saved and what the controls allow.
6. **Save a copy and return.** Export the settled session and find the snapshot.
   Quit normally, reopen the same build, find the session in local saved history,
   verify it and restore it paused. Re-find an entry and explain whether work has
   resumed. Do not resume or create another run during this check.

The last task uses local recovery; the ordinary interface does not currently import
an exported session folder. The journal can take any topic or form. Interesting,
ordinary or surprising prose is welcome; no preferred voice or writing score is
required for these tasks.

## If something goes wrong

Stop at the first failed operation or incomplete model response. Keep the message
and retained work. For this check, do not retry, skip feedback, change models or
extend limits to obtain four journals. Ask for help preserving or closing work when
needed; the observer records that assistance. Remaining tasks stay unattempted.

At the end, tell us what felt compelling, what was confusing, and what you would
try next. These materials prepare a human check; they do not record one as passed.
