# Ollama 0.40.4 startup and runtime boundary review

A source-level review found **no concrete change that blocks the existing isolated direct-`serve` recipe**, provided its checks remain enforced. This is conditional clearance for a separately identified prospective episode, not proof that the installed runtime is safe in every execution, identical to 0.40.3, or already qualified by a model run. Episode01's pre-spawn identity refusal remains valid and must not be rewritten.

## Boundary findings

| Boundary | Source finding and retained condition |
| --- | --- |
| HOME and conventional keys | `RunServer` and `initializeKeypair` are byte-identical. Direct `serve` checks the conventional private-key path and creates private/public keys if that private key is missing. Keep HOME unchanged and require the existing ordinary key metadata before launch; missing/replaced keys must abort. This is not a zero-race OS write prohibition. [Exact startup source](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/cmd/cmd.go#L2223). |
| Configuration and cloud | `envconfig/config.go` and recommendation-cache code are byte-identical. `server.json` is read by the configuration loader; it is not created there. `OLLAMA_NO_CLOUD=1` takes precedence. Recommendation refresh returns before network/signing/persistence; an existing conventional recommendation snapshot can still be read. Preserve metadata-only key/config before-and-after checks. This setting is not a network sandbox. [Configuration](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/envconfig/config.go#L393), [recommendations](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/server/model_recommendations.go#L151). |
| Model-directory writes | `Serve` is byte-identical. `OLLAMA_NOPRUNE=1` bypasses ordinary unused-layer/manifest pruning, but startup still calls split-model-directory cleanup and blob repair. It does **not** make the model tree read-only. Continue using only the already owned independent copy, with no shared-cache symlinks/hard links. [Startup maintenance](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/server/routes.go#L2437). |
| Request logs | The request-body file logger is unchanged and returns without creating its temporary directory when `OLLAMA_DEBUG_LOG_REQUESTS=false`. Keep `OLLAMA_DEBUG=0`. Ordinary server/runner stderr, access/status lines and model paths still exist; “request logging disabled” must not mean “no logs” or a blanket guarantee that no diagnostic can contain request-derived material. The runner log-verbosity function is unchanged. [Request logger](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/server/inference_request_log.go#L24), [runner logs](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/llm/llama_server.go#L596). |
| Host/port and subprocess | The host parser still accepts port 0, and direct `serve` passes it to `net.Listen`. Read the resulting nonzero loopback endpoint only from the owned log. GGUF runner launch still uses a local executable, loopback host and `--offline`. Darwin `SysProcAttr` remains empty, so no new process-group/session separation is requested by this launcher. Keep supervisor ownership checks, unreaped leader, bounded lifetime and scoped cleanup; source inheritance does not prove actual descendant membership or cover escaped descendants. [Host parser](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/envconfig/config.go#L18), [runner launch](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/llm/llama_server.go#L385), [Darwin attributes](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/llm/llm_darwin.go#L7). |

## Material runtime changes and limits

The reviewed release changes manifest verification and loaded-model reuse on the local chat path. A loaded v2 manifest can be reused after a name-to-digest link check without rehashing that blob on each request; legacy/copied manifests fall back to full selection. Do not describe the server as independently rehashing every model byte for every request. Keep the selected owned files hash-checked before launch and prevent external mutation during the episode. Chat message construction now clones retained model messages before appending request messages. [Manifest implementation](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/manifest/manifest.go#L1405), [model reuse](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/server/routes.go#L1595), [chat message construction](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/server/routes.go#L3598).

The llama.cpp pin advances from `b11351` to `b11521`; MLX and MLX-C pins also change. Several new branches concern decision models, embedding or MLX, which are not this selected GGUF prose-chat use. The llama.cpp change nevertheless means output, timing, memory, token accounting and completeness behavior need actual new evidence. No source-based equivalence claim is made. The complete upstream llama.cpp delta was not audited. [New llama.cpp pin](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/LLAMA_CPP_VERSION), [scheduler](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/server/sched.go#L588).

The executable/plist receipt does not independently identify every bundled helper or dynamic library. Runner lookup remains local and unchanged, but searches several package/build locations. Record the actual runner path/version visible in owned logs without treating it as an independently hashed full application bundle. Any unexpected runner path, runtime version, cloud behavior, or changed key/config identity requires stopping and reporting, not silently accepting a substitute. This review also does not establish absence of OS/compiler/GPU cache writes. [Runner lookup](https://github.com/ollama/ollama/blob/45e6011815c74acde6a346512856b69dd79dd22b/llm/llama_binary.go#L39).

## Conditions for the separate episode

Keep the existing 1,200-second supervisor, 1,140-second Start margin, 900 active-second application budget, 12 attempt slots, one model/parallel request, and all admission/stop rules. Use only the reviewed direct `serve` route and selected private cache; no `pull`, CLI `run`, GUI launcher, default-service discovery or automatic retries. Preserve the old selection and stage receipt, with an explicit reviewed 0.40.4 overlay rather than editing historical identities. The overlay/helper's own mocked qualification is a separate requirement from this source review.

No admission, process inventory, signal, UI action, local endpoint contact, runtime execution, model-asset read/copy or key/config content read was performed for this review. Only official public sources and explicit repository evidence were read; new files are review artifacts. Actual launch, model response quality, resource behavior and cleanup remain unexecuted by this reviewer.
