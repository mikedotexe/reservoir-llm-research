# Prospective journal-grounding review, 0.13.0

This protocol is written before any `reservoir-journal-v2` model output. It authorizes no service launch or request by the evaluation harness. The parent task owns the separately authorized native run, owned model process, qualification and shutdown. Existing v1 journals and receipts remain immutable.

## Question and scope

Does the new prompt produce four usable journal entries that identify the current observation correctly, transcribe supplied measurements accurately, keep prior journal language distinct from present evidence, and avoid unsupported scientific conclusions? Mechanical completion is assessed separately from prose quality. This is a small prospective product check, not a causal prompt experiment or a model benchmark.

The known v1 reference is the complete four-entry Gemma episode at steps 30, 60, 90 and 120, retained in `../2026-10-13-reading-0.12.2/real-model-export-01/quality-review-material.json` (SHA-256 `da9b912349e4a1efb60a07dac88cf12d35ac99246a41e7f3997c9ffc3d8b78a7`). Its passing replay receipt has SHA-256 `7cc9bc59a8ff6c27f5ab740e586d80821b4a383206b59b1606fb07dfd19094c1`. Earlier close-reading annotations remain historical and are not rewritten. These known errors informed the rubric, so v1 is a development/reference set, not a held-out test.

The core contract identifies legacy prompts as `reservoir-journal-v1` and new prompts as `reservoir-journal-v2` through `promptVersion`. Missing legacy metadata means v1. New observations, prompt wording, export identity and actual generated bytes must be bound before interpretation; response style is never used to infer a version.

The agreed v2 output guidance is an exact opening `Step N.` followed by one short plain-text paragraph, about 60–100 words, citing current recurrent RMS and separate reduced sensory fill and one cautious next observation/question. RMS at four decimals and fill at two decimals are acceptable; additional metrics are optional. No assistant preface or Markdown heading is requested. These are coverage/style expectations, not runtime parsing or scientific-acceptance gates. Do not impose them retroactively as v1 failures.

## Authorized bounded rehearsal

One v2 native session has at most four generation attempts, the same selected Gemma3:4b model manifest as the retained v1 session, context 4096, fixed maximum output 256 tokens and temperature 0. Use the established owned-process isolation and explicit readiness/Create/Start flow. Record the actual package SHA-256, version, model/runtime/staged-manifest identity, prompt version and newly selected owned endpoint before Start. Do not use or discover a default endpoint.

Use seed 20261013, cadence 30, requested pace 1000 ms per free numerical step, maximum 121 steps, four attempts, 600 seconds, 64 MiB storage, leak 0.65, noise amplitude 0.02, initial retention 0.955 and regulation enabled. The first reached bound holds/stops the session. No extra frozen-prompt comparison, parameter extension, provider substitution, sample replacement or automatic retry is included. Preserve failed, incomplete, cancelled, skipped or unstarted opportunities rather than reporting only successful journals. The parent may stop early for a concrete runtime or resource issue; retain the exact reason and do not fill missing entries with new requests.

The same seed/configuration does not make later v1 and v2 prompts identical: changed journal text changes feedback and subsequent numerical state. Compare each entry to its own supplied evidence. The first observation can share initial conditions, but this run does not establish a controlled causal benefit of prompt wording, memory, model choice or feedback. A matched frozen-observation comparison would be a separate authorization and protocol.

## Review contract

Review every retained attempt and all successful entries. Keep six dimensions separate:

| Dimension | Evidence and decision |
|---|---|
| Mechanical integrity/completion | Use pinned whole-bundle replay and exact source/save/application/memory associations. Report failed or incomplete attempts, real stop reason, token count and whether each journal actually applied. An integrity pass is not a quality pass. |
| Current observation identity | Check any current-step label against the current observation. A missing label is an omission, not automatically a false fact; historical or planned-step references need scope review. Prior application steps must not become the current observation label. |
| Numeric transcription | Check each explicitly labeled measurement against the relevant supplied current or clearly attributed prior evidence, allowing its stated rounding precision. Distinguish recurrent RMS/L2/coordinates from the separate sensory eigenvalues, top-eight entropy/head share and reduced fill. State coverage and unrecognized/ambiguous claims. |
| Memory attribution | Check whether a current claim repeats an obsolete value or heading from supplied memory. Record exact overlap as a carryover candidate, not proof that memory caused it. Correct attribution or explicit correction is different from copying a past value as current. |
| Inference and uncertainty | For each substantive interpretation, record supported-within-scope, contradicted, not-established or unresolved, with the actual evidence. Convergence, whole-spectrum uniformity, eigenvectors, spatial semantics, causality, training, learning and intent require their own support. Mentioning a word, denying an inference, or proposing a future test is not an error by itself. |
| Readability/style | Record directness, complete sentences, excessive boilerplate, misleading headings, unnecessary formatting and repetitive prose separately. Do not alter saved text or treat cosmetic compliance as scientific correctness. |

Deterministic checks are deliberately narrow extraction aids. They report spans, expected values, precision, scope uncertainty and omissions. They must not award a global “scientific pass” because no regex matched. Cue matching only directs manual reading; negated/qualified statements may be good practice. Every entry still receives a manual whole-text review, including claims outside the recognized grammar. No opaque composite quality score or statistical significance claim is planned.

For numeric comparisons, use one half of the final displayed decimal place (including exponent notation) plus a small allowance for eight-decimal prompt rendering. Whole-percent rounding is judged as such; for example 85.6189% legitimately rounds to 86%. A value that matches prior memory but misses current evidence is a carryover candidate, not authenticated causal contamination. Explicit historical comparisons and uncertain scopes are routed to manual review rather than mechanically declared wrong.

## Evidence and finish line

Before v2 generation, freeze this protocol, the machine-readable run plan, the checker/rubric identity and synthetic fixture test receipt. Bind the immutable v1 input hashes. Qualify the checker with positive, negative and ambiguous/negated examples; include missing measurements, rounding boundaries, current-versus-prior confusion, unsupported prose without trigger words and correct statements containing trigger words. Synthetic cases qualify bounded behavior, not natural-language completeness.

After the parent supplies the actual immutable v2 export, run the pinned offline integrity checker, then the same frozen quality harness on its bound review material. Retain exact originals, machine reports and independent manual annotations. Report all four opportunity outcomes, mechanical results and each quality dimension, with source/version identities and any deviations from this plan. A failed/incomplete run is an honest result and does not authorize another attempt.

Success for this work means a reviewable result with the above distinctions and limitations. If the prose improves, call it an observed improvement in this bounded episode only; if errors remain, name them. No system-wide learning, consciousness, deliberate intention, independent memory comprehension, cross-platform parity, long-duration model reliability, or physical power-loss durability claim follows.
