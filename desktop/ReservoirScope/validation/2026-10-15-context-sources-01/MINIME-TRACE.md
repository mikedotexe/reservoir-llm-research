## Context is route-specific

The ordinary `JOURNAL` route constructs an open invitation without automatic telemetry or previous-entry recall. It captures a before snapshot for the archive, later captures a post-generation snapshot, then saves the prose and separate metadata. The metadata names `state_at_invitation_not_supplied` and `post_generation_observation_not_generation_input`; its `automatic_telemetry_supplied: false` claim is explicitly limited to the **base invitation**. Historical cues, authored history or other separately delivered context must still be considered. A continuation hint may also be added. This is evidence separation, not proof that the complete provider request contains no historical material. [runtime.py:28116–28161](/Users/v/other/minime/minime_autonomy/runtime.py:28116), [expressive_journal.py:30–46,76–113](/Users/v/other/minime/minime_autonomy/expressive_journal.py:30).

`DAYDREAM` instead passes a previous-entry recall to the open invitation. Pressure and moment routes can supply measurements. The moment formatter separates “Measured state at capture” from “Historical event records”; recording age, event engine time and prompt-capture time remain different clocks, with unknown/mismatch labels. No conversion from these clocks to a sensation or a causal effect is established. ## Supplied context is not the same as an archive or an action

Open-expression paths suppress much routine operational/research context. Conditional activity status and historical cues can still be added, and backend adaptation can trim context. The Ollama path adapts system/user messages before sending them. Generation-record code retains adapted messages when captured, otherwise labels them reconstructed, alongside model/backend/attempt and response identities. Therefore an invitation or a journal header alone does not establish the exact provider exposure. No actual generation record was opened here. [runtime.py:55420–55561](/Users/v/other/minime/minime_autonomy/runtime.py:55420), [runtime.py:21631–21720](/Users/v/other/minime/minime_autonomy/runtime.py:21631), [runtime.py:56403–56508](/Users/v/other/minime/minime_autonomy/runtime.py:56403), [generation_record.py:355–465](/Users/v/other/minime/minime_autonomy/generation_record.py:355).

A prose mention and a recognized directive are distinct in this source. This trace does not audit every authority gate or establish that any particular action ran. ## A checked text-to-numerical path

In the self-experiment route, a `STIMULUS:` line is extracted from the generated response. `_text_to_features` takes the last 64 UTF-8 bytes, normalizes/pads them, uses a seed-42 random projection, and applies `tanh`; its default result is 32 floats. `_send_semantic` sends those features as a semantic WebSocket packet. Its successful-send log is **not** an application receipt, and exceptions are logged locally. [runtime.py:28430–28458](/Users/v/other/minime/minime_autonomy/runtime.py:28430), [runtime.py:29280–29320](/Users/v/other/minime/minime_autonomy/runtime.py:29280).

The Rust semantic receiver accepts the vector into a 48-value lane, zero-padding shorter vectors and distinguishing dimension-normalized ingress from exact dimensions. The sensory bus applies freshness decay and configured gains before constructing the input vector. Stable-core conditions can further hold semantic input out; the telemetry source distinguishes received input from admitted kernel activity. The ESN path constructs the reservoir input and calls `esn.step`; separate code projects sensory input for covariance updates. Thus receiving a packet, admitting it, changing recurrent state and measuring a later field are separate events. [sensory_ws.rs:845–861](/Users/v/other/minime/minime/src/sensory_ws.rs:845), [sensory_bus.rs:2070–2085,2918–2965](/Users/v/other/minime/minime/src/sensory_bus.rs:2070), [orchestration.rs:1232–1274,1392–1410](/Users/v/other/minime/minime/src/runtime/orchestration.rs:1232), [semantic_modality.rs:1–66](/Users/v/other/minime/minime/src/runtime/semantic_modality.rs:1).

The checked ordinary-journal and journal-persistence paths do **not** call that semantic sender. This is a scoped negative finding, not an exhaustive proof that journal text never returns through another action, later recall or external producer. The self-experiment path also does not establish ReservoirScope's durable save/readback/next-step application contract: it sends the stimulus before the later experiment journal write. No active lane settings, deployed executable, actual send, application event or numerical effect were observed here. ## Narrow app-design implication

Keep separate provenance for **current supplied measurements**, **historical prose**, **generated interpretation/imagined continuation**, and **recorded mechanical return**. Labels can identify source, clock, truncation and actual observed/applied steps without deciding what the writer should imagine or requiring a telemetry report. Archive-only measurements should not be displayed as supplied context; saved prose should not be promoted to a measurement or execution ledger. These are implementation options informed by source organization, not findings about the causes of either system's writing. No production change is made or recommended solely from this trace.

The current semantic receiver additionally has a typed 48+12 companion extension. Only its schema and input boundary were inspected; this does not establish that it is deployed or active. Source names such as “journal resonance,” and comments about experience, are not treated as evidence of subjective effects.
